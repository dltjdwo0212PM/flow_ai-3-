# 🧭 intake-clarifier (기획요청 되묻기 에이전트)

Flow 엔터프라이즈·공공 **기획요청**을 시니어 IT 서비스 기획자 관점으로 읽고, 개발 착수가
가능한 수준으로 끌어올리는 **"되묻기 질문"을 댓글 초안으로** 만든다.

- **형태**: Claude Code **서브에이전트** — 정의는 [`.claude/agents/intake-clarifier.md`](../../.claude/agents/intake-clarifier.md)
- **연동(읽기 전용)**: `flow_get_post`·`flow_list_project_items`·`flow_get_project`·`flow_list_project_participants`·`flow_search`
- **기본 대상**: `[PM] 엔터 기획 요청` (`1551252`)
- **출력**: `[내부 분석]`(성재만) + `[댓글 초안]`(고객용 `~니다체`)

## ⚠️ 이전 버전(planning-clarifier)과 달라진 점

| | planning-clarifier (구) | **intake-clarifier (신)** |
|---|---|---|
| 게시 | 자동 게시(매시간 루틴) | **자동 게시 금지 — 초안만** |
| 사람 개입 | 없음(무인) | **사람이 검토·게시 결정** |
| 분석 | 질문만 | **5축 갭분석 + 내부 메모 분리** |
| 질문 | 5~10개 | **기본 3개(최대 5), 닫힌 질문 우선** |
| 쓰기 도구 | `flow_create_comment` 포함 | **없음(읽기 전용)** |

→ 더 안전하고(삭제 불가인 댓글을 함부로 안 올림) 더 날카로운(공수·리스크·재활용을 캐는) 버전.

## 쓰는 법

이 세션/이 repo 기반 Claude Code 세션에서:

```
@intake-clarifier 1551252에 새로 올라온 기획요청 처리해줘
# 또는 특정 글:
@intake-clarifier 이 게시물(postId 78385395) 되묻기 질문 만들어줘
```

- 글 ID를 안 주면 최근 요청을 훑은 뒤 **"어느 글 처리할까요?"** 부터 묻는다.
- 결과로 나온 `[댓글 초안]`을 본인이 보고, 괜찮으면 **직접 Flow에 게시**(또는 "이거 그대로 올려줘" 하면 그때 게시 수행).

> 루틴(스케줄)으로 돌릴 수도 있지만, 이 에이전트는 **초안만** 만들고 게시는 사람이 하므로
> "무인 자동"과는 결이 다르다. 스케줄로 매일 새 글 초안을 모아두는 용도로는 쓸 수 있다.

## 출력 예시 (스타일 참고 — 실제 게시 아님)

> 요청: "[금융감독원] 쪽지·대화·알림봇 삭제 기능" (웹·서버·모바일, ~6/5)

**[내부 분석]** (성재만)
- 요청 유형: "삭제 기능"이라는 해결책 형태. 근본 니즈 = 메시지 잔존 최소화·로컬저장 선행 단계.
- 핵심 갭: 삭제의 의미(영구 vs 마스킹/숨김), 발신·수신 동기화, 규제 보존의무 충돌, 소급 범위.
- 리스크·공수 신호: 금융권 보존의무 ↔ 영구삭제 충돌 가능 → 법무/보안 확인 필요. 서버 마스킹·소급 적용 시 마이그레이션 공수 큼.
- 기존 기능 대체: '나만 삭제'·자동삭제 보존정책은 기존 알림/메시지 보존 설정과 중복 가능 → 재활용 검토.

**[댓글 초안]** (미게시)
> 요청 주셔서 감사합니다. 정확한 설계를 위해 아래 세 가지만 확인 부탁드립니다.
> 1. 쪽지·대화 삭제는 (A) 발신·수신 양쪽에서 제거 + '삭제됨' 표기, (B) 발신자 화면에서만 제거 중 어느 쪽일까요?
> 2. 서버 마스킹 시 원문은 (A) 완전 파기, (B) 보존 후 마스킹 중 무엇일까요? 금융감독원 보존의무와 충돌이 없는지도 함께 확인이 필요합니다.
> 3. 적용 범위는 (A) 신규 메시지부터, (B) 기존 누적 메시지 소급 포함 중 무엇일까요? (소급이면 마이그레이션 범위 산정이 필요합니다.)
